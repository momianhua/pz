# 设计决策与推理记录

本文记录可审查的工程决策、候选方案及验证依据，用于复现方案形成过程。

## ADR-001：使用 Adapter SPI 隔离引擎

**问题：** Pi 使用 stdio JSONL/RPC，OpenCode 使用 HTTP/OpenAPI 与 SSE，直接在业务流程中分别判断会形成条件分支扩散。

**候选：** 统一要求引擎提供 OpenAI API；业务层按引擎写分支；建立内部稳定 SPI。

**选择：** 建立稳定 SPI。它允许引擎保留最适合自己的原生接入方式，也把差异限制在一个目录内。

**验证：** Pi 与 OpenCode 的 Adapter 没有互相依赖；聊天页面只消费统一事件。

## ADR-002：逻辑会话与引擎 session 解耦

**问题：** 直接把原生 sessionId 返回业务层后，切换引擎会使已有会话标识失效。

**选择：** 网关生成逻辑会话，并维护一对多引擎绑定。

**代价：** 网关需要持久化映射并处理并发一致性。

**验证：** 切换后 logicalSessionId 不变，bindings 同时包含 `pi` 与 `opencode`。

## ADR-003：OpenCode 使用同步执行 + SSE 观察

**问题：** 单独使用异步 Prompt 时，调用方完全依赖全局 SSE 正确传递完成和错误事件；不同版本的事件顺序也可能变化。

**选择：** 先建立 `/event` 连接，再调用同步 `/session/:id/message`。SSE 提供实时文本、工具和权限事件，同步响应提供确定性的最终消息兜底。所有事件按 sessionID 过滤。

**代价：** 网关需要同时管理一个长连接和一个请求，并对流式文本与最终文本去重。

**验证：** Adapter 协议测试模拟 OpenCode Server，确认跨 session 事件被丢弃且最终响应可补齐文本。

## ADR-004：使用标准消息历史进行跨引擎迁移

**问题：** 不同引擎的内部状态、工具轨迹和压缩摘要不可直接互换。

**候选：** 序列化原生 session；完全不迁移；迁移标准消息；额外生成迁移摘要。

**选择：** 当前版本迁移标准消息，保持确定性和可测试性。长对话的摘要迁移作为扩展点。

**限制：** 工具的隐藏状态不会迁移；有副作用的工具调用不会在切换时重放。

## ADR-005：同会话串行、跨会话并行

**问题：** 同群并发请求可能同时创建绑定或打乱上下文顺序。

**选择：** 使用 `(tenantId, conversationId)` keyed lock。同键串行，不同键不互相阻塞。

**验证：** 契约测试验证绑定复用；结构上不存在全局执行锁。

## ADR-006：mock 与 real 使用同一网关路径

**问题：** 评测环境可能没有模型账号或无法安装两个外部引擎。

**选择：** mock Adapter 实现同一 SPI，而不是在 controller 中硬编码演示响应。因此 mock 仍覆盖路由、会话、持久化、权限和 SSE 主流程。

**限制：** mock 只能证明网关行为，真实引擎连通性需在配置好 provider 后单独验收。

## ADR-007：权限在网关执行

**问题：** 将权限写进 Prompt 无法阻止恶意或错误的工具调用。

**选择：** 网关校验引擎 allowlist；后续工具权限也应在网关工具代理层执行。Prompt 只负责行为提示，不作为安全边界。
